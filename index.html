From dedicated random sessions to production logs

The deployed system combines quantile calibration, pointwise IIPS@K, and one-pass uncertainty estimation. It uses full-slate production logs, enabling retirement of the dedicated random-session branch. Position-one replay baseline: uniform-random logging (WSDM 2011), evaluated at the first position. Requires logging support and propensity assumptions.

Make uncertainty practical: 50 passes become one

M separate reads are replaced by one shared read. The illustration shows tile 1, tile 2, and tile M: same rows in every tile, with a different seeded binary mask. M = 50 replicas. Columns are mask slots, not slate positions. Mask slots: 0 1 0 1 → session weight 2 (illustrative). The illustrated masks are conceptual, not experiment data.

  1. Read each session once and compute g(s), the session's OPE contribution.
  2. Fan that contribution into all tiles. Sum each row's bits for its weight, then multiply g(s) by that weight.
  3. Keep replicas separate: the 50 masked accumulators collect weighted contributions separately by replica.
  4. Normalize each sum by the common mask-slot count times session-count denominator. This produces M estimates.
  5. Compute sample variance across the estimates.

The collection line routes separate replicas; it does not pool them into one estimate. Masks and updates still scale with M.

Within 1% relative variance error vs. same-mask multi-pass reference. M = 50 is the number of replicas; K is slate depth. The factorization reduces I/O passes, not a measured 50x wall-clock speedup. Detailed replica-count and dropout sweeps are outside this poster's scope; this comparison does not establish formal confidence-interval coverage.

Low pointwise error through K = 60

Under the pointwise assumption, reward at a position depends on its item without modeling dependence on preceding items. Pointwise IPS is established prior work; the empirical comparison tests its suitability for this Feed workload.

Pointwise has lower error here; cause not isolated. Unstable sequential weights are one possible reason. Higher nMSE alone does not distinguish weight instability, propensity error, and a misspecified dependence model, or prove that cross-position reward effects are absent.

Calibrate scores before computing propensities

Across ranker versions, objective re-weights can change score scales. Raw model scores (logits) passed directly to softmax can confuse scale changes with preference changes. The calibrated path is: equal-population score bins (quantile bins with equal item counts), observed response rates, then softmax. The resulting propensity estimates are used for weighting. Calibrate candidate and logging rankers separately. Weight: candidate / logging probability (πe / πl). Softmax is retained.

The schematic is conceptual; it contains no measured score distributions. Rank-preserving re-scaling is the lemma's guarantee. Arbitrary re-weights may change order; exact raw-to-calibrated AUC preservation is not asserted.

Limits and interpretation

Comparison limits

Logging data and evaluated positions differ. Small model sets; logging support assumed.

Remaining limitations

Earlier candidate-selection bias is not corrected. Overall agreement is not attributed to each component.
